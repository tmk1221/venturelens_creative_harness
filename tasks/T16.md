# T16 brandkit: three layers + canonical template
Goal: make the kit canonical and fillable by non-designers; separate universal craft from brand tokens from per-video look. Supersedes the guessed values from T01.
Read first: `docs/research-brand-consistent-generation.md` §6 (table, skeleton, templates, QA), existing `packages/brandkit/` (schema, compile, lint, kits/acme/NOTES.md).
Build (only under `packages/brandkit/` and `docs/BRAND-KIT.md`):
- Three layers, merged in order house → brand → look, each field overridable downward only where marked:
  1. `house/house.yaml` — Travis's universal craft rules, shipped with defaults from research §5/§6: still-prompt structure + exclusions, motion-prompt structure (single action, describe only the delta), negatives caps, never-generate-a-screen/logo/text, references-not-chaining, safe areas (title 80% / action 90%) per 16:9 and 9:16, easing + duration scale defaults, max simultaneous moves, 60/30/10 default ratio, clip length ≥ beat + 1 s handle, QA checklist items. Every default carries a `source:` note (research / Gio backlog / audit lesson) so Travis can see why it exists and change it.
  2. `kits/<client>/brand.yaml` — brand tokens only: names, palette (plain-English colour name for prompts + hex for HTML only), type roles, logo variants as SLOTS (`file: null, status: pending` is valid and reported, not an error), voice_and_mood, visual_style (lens/lighting/time of day/grade), wardrobe_and_props accents, caption style, sfx palette, names allow/forbid + pronunciation list, characters, overrides of house motion defaults.
  3. `looks/<name>.yaml` (optional, per video/series): setting, wardrobe variant, mood, extra references.
  - `references/` spec: 3–5 approved hero frames (environment, detail, human presence; same lens/light/grade), optional character + location sheets; validated count + existence; hashes included in `kit_hash()`.
- `kits/_template/` — fully annotated skeleton: every field marked REQUIRED/OPTIONAL with a one-line "how to fill this in" for a non-designer. `python -m brandkit init <client>` copies it.
- `python -m brandkit status <kit>` → readiness report: filled / pending / guessed per field, what each missing item blocks (e.g. "logo pending → overlays with logo cannot render; stills unaffected"). A field can be marked `guessed: true`; status lists them. Re-mark every guessed value in kits/acme as guessed; set Acme logos to pending slots (SVGs are being redrawn); REMOVE the invented photographic look and leave it as a pending required field.
- Compilers updated: `still_prompt(slots, kit, look)` and `motion_prompt(slots, kit)` template functions producing the research §6(c) templates with purity lint applied; keep brand.css / design.md / captions.json outputs. `qa_checklist.md` emitted from house + kit.
- `docs/BRAND-KIT.md`: one page — the three layers, what goes where and why, how to fill a kit, what is deliberately excluded from image/video prompts.
Acceptance: existing tests still pass (update where the schema moved); new tests: layer merge + override rules, pending slots valid, status report content, init from template validates as "incomplete but well-formed", prompt templates never leak hex/font/brand words, Acme kit loads with its pending/guessed items listed.
Out of scope: automated OCR/VLM checks, touching live skills.
