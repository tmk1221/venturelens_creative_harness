# T31 spend safety: no click spends without a shown estimate, real cost recorded, fake mode explicit
Why: a real project must be safe to open. Today the web pre-authorises every Generate against a `demo` budget
the API creates on the fly (`web/src/enrich/api.ts:121` sends `budget:'demo', cap:1000, unit:'usd',
covers_downstream:true`; `post_api/routes/workflows.py:326-331` calls `ensure_budget` from the request body),
real-mode Higgsfield workers record `{"amount": 0.0, "unit": "credits"}` (`recipes/workers/still_generate.py:48`,
same in `endframe_generate.py`, `video_generate.py`), so the cap never bites, and `scripts/dev.sh` never sets
`POST3_FAKE_PROVIDERS=1`. AGENTS.md: "Nothing spends money without an explicit authorisation recorded in the
request. Enforce in the core." Absorbs the remaining part of T13c (batch "Generate N … ≈ X credits" confirm).
Read first: `queue/enqueue.py`, `queue/authorisation.py`, `queue/executor.py` (`_record_cost`), `recipes/models.py`
(`estimate_cost`), `recipes/workers/_common.py` (`fake_mode`, unused `require_fake_or_die`), `graph/plan.py`,
`post_api/routes/workflows.py` (`RunRequest`, run route), `post_api/routes/queue.py` (budgets), `web/src/enrich/api.ts`,
`web/src/enrich/CardBody.tsx` (plan → "Estimated cost" → Confirm).
Build:
1. Core: a budget is created only by an explicit budget call (`post budget set`, `PUT …/budgets/{id}`), never as a
   side effect of `run`. Remove `cap`/`unit` from `RunRequest`; a run naming an unknown budget is refused (409 with
   the reason). Budgets carry the provider's unit (`credits` for Higgsfield, `usd` for Deepgram); `enqueue` refuses
   a spends node whose estimated cost unit differs from its budget's unit, and refuses when the plan's estimate
   for the authorised nodes exceeds the budget's headroom (not just headroom <= 0).
2. Workers: in real mode record the pre-call estimate from `models.estimate_cost` as the job's cost (mark it
   `"estimated": true`) unless the provider returns an actual amount; if no estimate is available, refuse to run
   (exit 2, one-sentence reason) instead of spending blind. Never record 0 for a real call.
3. Executor `_record_cost`: sum only amounts in the budget's unit; a mismatched unit fails the job with a clear
   cause instead of being added.
4. Web: Generate/"run from here" first calls plan, shows "N stills, M videos ≈ X credits", and Confirm creates one
   budget for exactly that click (id from workflow + time, cap = shown estimate, unit from the plan) then runs
   with an authorisation naming those node ids. `covers_downstream` stays allowed, but the cap is the shown
   estimate, so a chain can never spend past what the person saw.
5. Mode is explicit: `scripts/dev.sh` sets `POST3_FAKE_PROVIDERS=1` unless `POST3_REAL=1` is set; `GET /api/doctor`
   reports `providers: fake|real`; the web shell shows a persistent "REAL: spends credits" badge in real mode.
   Use `require_fake_or_die` where it was meant to be used, or delete it.
Acceptance: pytest for each refusal (unknown budget, unit mismatch, estimate over headroom, real-mode worker with no
estimate exits 2, no 0-cost record in real mode, mismatched unit not summed); API test that `run` no longer creates
budgets; vitest/Playwright (mocked API): Confirm shows the estimate and sends one budget + one authorisation with
explicit node ids; `make dev` starts in fake mode and the badge shows only under `POST3_REAL=1`. All suites green.
Out of scope: real provider calls (T18), per-project spend dashboards.
