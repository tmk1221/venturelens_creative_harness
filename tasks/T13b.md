# T13b beats: suggest, add visual, hover (after T13a)
Goal: mark what the viewer sees, on the transcript. No generation here (that is T13c).
1. Spans as edit ops (add / resize by word / change layer / remove); same-layer overlap refused with the conflicting span named; overlays are an independent layer. API + tests.
2. Select words → toolbar "Add visual ▸ live action | motion graphic | overlay | my footage | keep A-roll" + optional direction → saved span (solid underline, tinted) + a card in the right rail in transcript order; click words ↔ card highlights the other; edit/remove; manual choice overrides suggestions on the same words (preview the impact first, as the old editor did).
3. "Suggest visuals" (whole cut, a section, or the selection): backend job through the TextProvider/terminal-agent pattern with `brandkit.writer_context` (identity, personality, world) + the words; returns proposals {word range, kind, one-line brief, rationale}; validated (anchors exist, no same-layer overlap, within scope); stored as suggestions, never as spans. Fake provider in tests; chunk long transcripts by section.
4. Hover card on any dashed span: kind, brief, rationale, Accept · Adjust · Dismiss; header "Accept all (N)" skips blocked ones and says how many; dismissed ranges are not re-suggested. Hover on a saved span: kind, brief, and (once T13c exists) thumbnail + state.
5. Take swap under a span: span follows when the new read's words map (fuzzy align); otherwise mark `needs_review` and list it in a "Needs you" panel — never silently dropped.
Acceptance: pytest for ops/validation/suggestion lifecycle/remap; Playwright: add visual, overlap refusal, suggest → hover → accept/adjust/dismiss, accept all, take swap remaps a span.
