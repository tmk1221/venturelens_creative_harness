# T05 queue + executor
Goal: run planned nodes durably. Queue is derived from the graph; SQLite makes it restart-safe.
Read first (read-only): `~/cc/post/backend/app/jobs.py` (lanes, Resolve lock, interrupted state, credit-limit hold — port the ideas), T03 runner, T04 plan/state.
Build `packages/post_core/post_core/queue/` (stdlib sqlite3):
- `db.py`: `<root>/.post3/queue.db`, versioned migrations. Tables: job(id, workflow_id, node_id, input_hash, lane, state queued|running|ok|failed|retry_later|needs_human|interrupted|cancelled, cmd_json, authorised_by, budget_id, attempts, not_before, created/started/finished, summary), event(job_id, seq, kind, json), budget(id, cap, spent, unit).
  The full command is recorded at enqueue time. One connection per call site with explicit close (the old app leaked FDs).
- `enqueue.py`: `enqueue(plan, authorisation)`; refuses a `spends` node without an authorisation naming a budget with headroom; idempotent on (node_id, input_hash) while a job is live (no double spend).
- `executor.py`: worker loop with lane concurrency (config: single=1, render=1, remote=8, design=6), a cross-process `resolve` resource lock (flock) for nodes that declare it, picks jobs whose upstream is done, runs via T03 runner, writes events, on success moves outputs into the artifact dir + manifest atomically, adds `cost` events to the budget; over budget → remaining spend jobs become needs_human.
  exit 3 → retry_later with not_before, and the lane holds until then (a provider limit is not a failure). On startup: running → interrupted, then requeued if the node is still ready. Downstream nodes are enqueued automatically when they become ready and need no new authorisation; spending ones wait unless the batch authorisation covered them.
- Failure summaries: one sentence + cause key for grouping.
Acceptance (pytest, fake workers from tmp scripts): dependency order; lane limits honoured; restart mid-run recovers; no duplicate job for same hash; spend refused without authorisation; budget cap stops further spend; retry_later holds lane then resumes; failed job leaves node `failed` and downstream blocked; events persisted in order; resolve lock serialises across two executor processes.
Out of scope: HTTP/SSE, real generators.

(2) The executor writes the `failed.json` marker that `state.py` expects; add a test through a real fake worker. (3) NodeType gained `uses_brand_kit`; approvals revocation lives in `graph/revocations.json`.
