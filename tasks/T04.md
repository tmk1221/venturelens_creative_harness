# T04 build graph
Goal: the content-addressed graph that is the app's only state system (ARCHITECTURE §1, plan §7).
Read first: `docs/ARCHITECTURE.md`, `packages/post_core/post_core/{model,store}` (T02), `workers/contract.py`.
Build `packages/post_core/post_core/graph/` (stdlib + pydantic):
- `types.py`: handle types `image, video, audio, prompt, text, character, brand, words`. NodeType: id, inputs{name:type, required, many}, outputs{name:type},
  params schema (pydantic model), `kind`: compute | pick | approve | source, `spends: bool`, `lane`, `estimate_cost(params)->Cost|None`, `check(artifact_dir)->bool`.
- `registry.py`: register/get node types; built-ins: `source.file`, `text.prompt`, `human.pick` (chooses one of many upstream outputs), `human.approve`. Compute types come later (T12); tests register fakes.
- `workflow.py`: Workflow(nodes, edges, recipe_id, brand_kit_hash) pydantic + validation: types match on every edge, required inputs wired, no cycles, `many` respected. UI positions live in a separate `layout` field that never affects hashes.
- `hashing.py`: `input_hash(node)` = sha256 over canonical JSON of (type id + type version, params, sorted upstream output content hashes, brand_kit_hash if node consumes brand). Pick nodes hash the chosen option; an unmade pick = unresolved.
- `state.py`: derive per-node state from disk only: `unresolved | blocked | ready | done | stale | needs_pick | needs_approval | failed`. Artifact dir = `<root>/.post3/artifacts/<node_type>/<input_hash>/` with `manifest.json` (outputs with sha256, prompt, cost, worker, finished_at). Done = manifest exists + check passes. Stale = a previous manifest exists for this node id under a different hash (keep a per-node `history`). Failed = last attempt record for this hash failed.
- `plan.py`: `plan(workflow, targets=None, from_node=None)` → ordered runnable nodes, which need authorisation (`spends`), total estimated cost, and what is blocked on a human. Pure function, no side effects.
- `approvals.py`: approve/revoke by content hash via the store.
Acceptance (pytest, temp dirs, fake node types): edge validation errors; hash stable across key order/layout changes; param change → that node and all downstream stale, siblings untouched, old output still listed; pick change re-hashes downstream; brand hash change only affects brand consumers; plan ordering, cost total, spend flags, run-from-node; approval bound to content hash invalidates on new output.
Out of scope: executing anything (T05), HTTP, UI.
