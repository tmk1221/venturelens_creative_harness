# T17 brandkit: split by medium, derive style from images
Goal: restructure the kit the way Travis thinks about it (decided 2026-09-21). Supersedes parts of T16.
Decisions: (1) stills, video and animation are different problems and get separate kit sections; (2) reference images are NOT attached to generations as style anchors (they overfit subject/setting) — they are source material from which a written style block is derived; (3) character/location consistency is NOT in the kit — it belongs to the project cast registry and beat graph (later task); (4) the still style block is a brand default that a series/look may override.
Read first: `packages/brandkit/` as it stands, `docs/BRAND-KIT.md`, `docs/research-brand-consistent-generation.md` §1–3.
Build (only `packages/brandkit/`, `docs/BRAND-KIT.md`):
- `brand.yaml` layout: `core` (name, industry, mood, colours: each {name_plain, hex, role}); `stills` (style_block: {text, version, derived_from: [file hashes], status}, accents: how brand colour enters as wardrobe/prop/light, negatives ≤8); `video` (camera_personality, pacing_default, negatives ≤6); `animation` (type roles, logo slots, grid/safe areas, easing, durations, colour ratio, caption style, sfx palette, names/pronunciation). Remove `references` as a required field and remove `characters` from the kit. Migrate kits/acme and kits/_template; prune Acme `core.colours` to entries that are real brand colours per DESIGN.md (CSS-variable-only entries like hair/border/line move under `animation.css_vars`, still marked guessed).
- `looks/<series>.yaml` may override `stills.style_block`, `stills.accents`, `video.camera_personality`; nothing in `animation` except caption style. Merge order house → brand → look, tested.
- Style axes as data (`house/style_axes.yaml`): colour (hues, scheme, saturation, temperature, shadow/highlight tint, black level), light (quality, direction, contrast, motivation, atmosphere), lens (focal length, depth of field, height/distance, anamorphic traits), composition, texture/medium, production design, people. Each with a one-line plain-English explanation and 3–5 example phrasings.
- `python -m brandkit derive-style <image_folder> [--kit <client>] [--look <series>]`: builds a contact sheet + a prompt asking a vision model to describe ONLY what the images share along the style axes, explicitly ignoring subjects, settings, text and logos, and to return JSON {axis: phrase} + a ≤90-word style_block. The model call goes through a small `VisionProvider` protocol; ship a provider that shells out to a terminal agent CLI (`claude -p` with the image paths; configurable command) and a fake for tests. Output is written as a DRAFT (`style_block.draft.yaml`) for a human to edit; `brandkit accept-style` promotes it, bumps version, records source image hashes. Purity lint applies (no hex, font names, brand words, quoted text, named subjects).
- `python -m brandkit test-style <kit> [--look]`: emits six still prompts for deliberately unrelated subjects (person at desk, exterior street, object macro, two people talking, empty room, hands on tool) using the style block — prompts only, NO generation — so a human can run them and judge family resemblance.
- Three separate prompt builders with separate docs: `still_prompt` (content slots + style block + accents + continuity refs passed in by caller, never from the kit), `motion_prompt` (camera, one subject action, statics, pacing; never restates style), `animation_brief` (tokens + logo paths + rules for the HyperFrames agent). Version/hash of the style block is returned with each still prompt so the graph can mark frames stale when style changes.
- Rewrite `docs/BRAND-KIT.md`: one page, three medium sections side by side, what the kit is NOT (characters, locations), the derive → edit → test → accept loop.
Acceptance: all tests green; new tests for medium split, look override rules, derive-style with fake provider (draft written, purity enforced, subjects stripped), accept-style versioning, test-style output, builders never cross-contaminate (no hex in still/motion prompts; animation brief contains hex). `brandkit status acme` reflects the new layout.
