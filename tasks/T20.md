# T20 brandkit: first-principles core, positive-only, generate-everything
Decisions (Travis, 2026-09-21): the "Shared core" proposal is approved. The kit must be GENERATABLE end to end — take a first guess at every field, marked guessed — and must use POSITIVE definitions only: no `forbid`, no "never", no brand-level negatives. Any beat may warrant anything; the kit describes what the brand IS, not what is disallowed.
Read first: `packages/brandkit/` as it stands, `docs/BRAND-KIT.md`.
Build (only `packages/brandkit/`, `docs/BRAND-KIT.md`):
- New `core`: `identity` {name, what_they_do, who_they_serve}; `colours` = 3–6 brand colours with role ∈ {primary, secondary, accent, dark_neutral, light_neutral}, each {name_plain, hex}, plus `world_tone: light|dark` and `dominant: <role>`; `typography` {heading, body, mono?: family, source (google|file), file?}; `logos` (moved here from animation; slots as now); `personality` {is: [3–5 adjectives], voice: one sentence}; `world` {places: [], people: [], objects: [], textures: []} — subject matter that belongs in this brand's pictures, positive only; `names` {official: [], products: [], pronunciation: []}; `sources` [{kind: website|style_guide|file, ref, fetched_at}].
- REMOVE: `names.forbid`, `stills.negatives`, `video.negatives`, any "never …" phrasing in kit text fields, `qa_checklist_extra` items phrased as prohibitions (rephrase positively: "Light theme: cream ground, light cards"). Lint: replace the forbidden-names check with "on-screen product/feature names must come from names.official/products" reported as a WARNING with the unknown name, never a failure. Universal technical defaults (no generated text/logos/screens — a model limitation, not a brand rule) stay in `house/house.yaml` as DEFAULTS that a per-beat slot `allow: [text|logo|screen]` can lift; say so in the docs.
- `animation` shrinks to behaviour: layout/grid, motion notes, colour_ratio, caption_style, sfx_palette, css_vars.
- UI shades are GENERATED: `derive_ui_shades(colours, world_tone)` produces ground/surface tiers/ink tiers/hairline/accent wash from the brand colours (mix in OKLCH or simple sRGB lerp; stdlib only), checks WCAG contrast of ink on each surface (≥ 4.5), and writes them into brand.css. `animation.css_vars` holds only explicit overrides. For Acme, record today's brand.css values as overrides so its rendered look does not change.
- Generate everything: `python -m brandkit init <client> --from <url> [--guide <pdf|md>]`: fetch the site (urllib; one page + linked CSS; cap sizes; tests use saved fixture HTML/CSS, never the network), extract colour frequencies from CSS (custom properties first), font families, the header logo (inline SVG or img src → saved under assets/), title/meta/hero copy; then a `TextProvider` (same pattern as VisionProvider: shells to a configurable terminal agent; fake in tests) drafts identity, personality, world, names, style_block, accents, camera_personality from the copy. Everything written with `guessed: true` and a `sources` entry. `brandkit status` shows guessed count.
- Writing YAML must PRESERVE comments: switch kit writes (init, accept-style) to `ruamel.yaml` round-trip (add dependency) so annotated files survive.
- Migrate `kits/_template` (annotated, positive-only) and `kits/acme`: keep Travis's annotated style (a note above every field: what it is, who reads it, how it is used). Acme: map colours to cream = light_neutral, charcoal = dark_neutral, ochre = accent (primary = charcoal-on-cream world, dominant light_neutral); take a first guess at `world` for an IT hardware / help desk / cybersecurity / automations firm serving small and mid-size businesses (places, people, objects, textures), personality, names (no forbid list — move the old invented names into NOTES.md as history only). Rephrase style_block/accents/camera_personality positively and make the style block's light work indoors and out ("soft, diffused light from one side").
- `writer_context` now returns identity, personality, world, accents, camera_personality.
- Rewrite `docs/BRAND-KIT.md` to match, plain language.
Acceptance: all tests green (update for the new schema); new tests: positive-only schema rejects a `forbid` key with a helpful message; derive_ui_shades contrast; Acme overrides reproduce today's brand.css hexes; init --from with fixture site produces a loadable all-guessed kit with colours/fonts/logo extracted; comment preservation through accept-style; lint warns (not fails) on unknown names; per-beat `allow` lifts a house default.
