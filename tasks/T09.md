# T09 export: Cut → OpenTimelineIO
Goal: one-way, versioned hand-off to DaVinci Resolve (plan §6). Never touches Resolve itself.
Read first: `post_core/edit/ranges.py` (`timeline()` is the only source of timeline time), T02 model.
Add dependency `opentimelineio` to packages/post_core/pyproject.toml (optional extra `export`), install into the venv.
Carry-over from T08: add `fps: Rational` to Cut (additive, default 24000/1001) and make `timeline()/word_at()/time_of()` read it (keep the parameter as an override).
Build `packages/post_core/post_core/export/`:
- `otio_export.py`: `export_cut(project_root, cut_id, version=None) -> path`. Tracks: V1 = chosen angle per passage (real absolute source path as file URL, source range from sync offset + word times + trims/handles, available_range start from the source's probed timecode, rate from probed fps); V1-alt (disabled) = the other angle(s) of the sync group at the same offsets; V2+ = picture spans with a `done`+approved asset (lowest free track per clip at its own frames), gaps elsewhere; overlay tracks above; A1 = clean audio source of the sync group; A2+ = asset audio. Markers for sections, orphaned spans, and spans with no approved asset ("MISSING: <kind>"). Metadata `post3` namespace on every clip: passage/span id, asset content hash.
- Versioning: output `<root>/exports/<cut name> v<N>.otio`, N = next free; never overwrite. `manifest.json` beside it listing clips + hashes. `patch_export(cut, since_version)` → a timeline containing only clips whose asset hash or range changed since that manifest, at their timeline positions.
- Frame maths in rational arithmetic; correct at 23.976 and 29.97; no float accumulation across passages.
Acceptance: pytest builds a small fixture project (2 angles + audio, 3 passages reordered, 2 spans, 1 overlay) and asserts: track layout, clip source ranges to the frame, disabled alt track, lowest-free-track placement, version increments without overwrite, patch export contents, round-trip `otio.adapters.read_from_file` succeeds. H1 (human Resolve import) stays unverified — say so.
Only touch `post_core/export/`, `tests/export/`, pyproject.toml, and the carry-over edits.
