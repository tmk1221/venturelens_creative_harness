# T41 every card number visible on the words; no status badges in the header; live brand style guide in Ingest
From Travis's first real use (2026-10-13, Show Demo project, 8 proposals on a 70-word transcript):
1. Badges: the rail shows cards 1–8, but the transcript shows only some numbers (2, 4, 6). Proposals overlap
   (several start on the same line or cover the same words), so their badges are drawn on top of each other.
   Fix: every proposed/accepted card's number is visible on its passage. Badges for passages that start on the
   same line sit side by side (never stacked at the same x/y), and overlapping passages get separate underline lanes
   (offset dashed lines, picture vs overlay) so you can tell where each starts and ends. Hovering a badge highlights
   only that passage. Test: 8 overlapping fixtures → 8 distinct, non-overlapping badge boxes (bounding-box check in
   Playwright).
2. Header: remove the "guessed" kit-status badge and the "REAL: spends credits" badge from the shell header. Guessed is
   the normal state and the kit loads automatically. Keep the kit picker. Keep real/fake mode in `GET /api/doctor`
   and the startup log; spending stays gated by the cost confirm (T31).
3. Ingest page: a "Brand" panel showing the project's kit as a live style guide, i.e. the kit's design-system page
   (`brandkit render-design-system` → `index.html` + `tokens.css`) in a sandboxed iframe served by the API
   (`GET /api/projects/{pid}/brand/…`, read-only, path-confined to the kit's `design-system/`). Live means it
   re-renders when the kit's files change (mtime check on request, or a Refresh button at minimum). If the kit has no
   rendered page yet, render it on first request. Show the logo, colours with names, type and the approved-look
   image if `assets/approved-look-*.png` exists.
Acceptance: vitest + Playwright (mocked) for badges and header; API tests for the brand route (path confinement,
re-render on change, temp kit); tsc clean; all suites green.
Out of scope: editing the kit in the app.
