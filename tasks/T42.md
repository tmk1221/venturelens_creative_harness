# T42 project picture mode (audio-only, full B-roll) for the suggester; re-running Suggest replaces, never stacks
From Travis's first real use (2026-10-13). The Sample piece is Sample's audio only with 100% generated B-roll, but the
suggester's rules assume a presenter on camera, so it proposed "A-roll: the presenter stays in frame". And each Suggest
run added a new set on top of the pending one: 7 pending proposals, three pairs on identical word ranges.
Read first: `post_core/edit/{suggest_prompt,suggest_context,suggest_provider}.py`, `post_api/routes/suggest.py`, the
Project model + `PATCH /api/projects/{pid}` (T33), `web/src/suggest/`, the Visuals rail cards (T40/T41), T30a medium
vocabulary.
Build:
1. `Project.picture_mode: "presenter" | "audio_only"` (default `presenter`), shown as a setting on Ingest/project
   settings and editable via PATCH and `post project set --picture-mode`. The EDITORIAL RULES block is removed from
   the suggest prompt in both modes, and so is the "which rule" rationale wording: the rationale says, in plain
   language, why this picture fits these words. In `audio_only` the prompt says there is no presenter picture and
   every second of the cut needs a picture (never medium `aroll`, never `behind` overlays). Full coverage is a hard
   guarantee enforced in code after the agent replies, not a prompt hint: every word of the scope is covered by
   exactly one picture beat, contiguous, no gaps, no overlaps, never `aroll` (aroll proposals are dropped; gaps are
   closed by extending the nearest beat, overlaps trimmed/merged, an uncovered stretch goes to the nearest beat).
   Test: a reply with gaps and overlaps comes out as an exact tiling of the transcript, so the whole transcript
   shows highlighted in the editor. Prompt snapshot tests for both modes.
2. Re-running Suggest over a scope replaces the pending (not accepted, not dismissed) proposals inside that scope, so
   there is one proposal per passage. If the reply proposes two different ideas for the same words, keep one card with
   the second as an alternative ("Variant B") the person can switch to on the card. Accepted beats are untouched.
   Tests: two runs → no duplicate ranges; accepted beat survives a re-run.
3. Accepted cards keep their number badge on the card and on the words (T41 noted they lose it).
Acceptance: pytest for picture mode (prompt, validation, exact tiling), replace-on-rerun and variants; vitest + Playwright (mocked)
for the setting, variant switch and accepted badges; tsc clean; all suites green. Set the real Sample project and the
Show Demo project to `audio_only` via the CLI (free, writes only their `.post3/project.json` on the T7; authorised).
Out of scope: generation changes.
