# T11 web: shell + transcript editor v1
Goal: the first screen an editor uses — read the transcript, cut by deleting words, reorder, pick angles, watch it play. Plan §3.1 (borrowed patterns), §6 (proxy playback).
Read first: `packages/post_api/` routes + `python -m post_api.openapi`; `post_core/edit/ops.py` + `ranges.py` (the server owns edit logic and timeline maths — the client NEVER recomputes them); for interaction patterns only (read-only, do not copy code): `~/cc/post-transcript-first/frontend/src/{Transcript.jsx,transcriptSelection.js}`.
Build `web/` (Vite, React 19, TypeScript strict, Tailwind 4, zustand; vitest + Playwright). API types generated from OpenAPI (`npm run gen:api`), no hand-written response types. Dev proxy `/api` → the FastAPI port.
- Shell: project list/open, left nav (Ingest · Edit · Deliver), a jobs drawer fed by the SSE stream (state, progress, prompt, cost), a "needs you" counter. Plain, dense, keyboard-friendly; no marketing styling. Light and dark.
- Edit workspace: cut switcher (master + derived cuts, aspect badge) · transcript pane · monitor · (right rail reserved for T13, render an empty "Visuals" placeholder).
- Transcript: one continuous virtualised surface (must stay smooth at 20k words; test with a generated fixture); words grouped into passages with a thin divider + source/angle chip where the passage changes; deleted words are hidden by default with a "show cuts" toggle that renders them struck-through and restorable. Native mouse selection in either direction + shift-arrow keyboard selection, snapped to word boundaries; paint-then-commit during drag. Selection toolbar: Delete (⌫), Restore, Set angle ▸, Move (drag a selected range to a drop caret between words), Swap take ▸ (lists other ranges whose text fuzzy-matches the selection — server endpoint; add it to post_core/edit + post_api if missing, with tests), Derive short from selection. Suggestions: "Remove fillers" / "Remove long silences" show proposed ranges as dashed marks with accept-all / accept-one, never auto-applied.
- Every edit = one `POST …/ops` with `expected_rev`; on 409 refetch and tell the user; optimistic UI only for selection paint. Undo/redo (⌘Z / ⇧⌘Z) call the server. Gesture = one undo step.
- Monitor: plays PROXIES over HTTP Range. Playback follows the cut: the server returns the segment list (`timeline(cut)`); two pooled `<video>` elements, the idle one preloads and seeks to the next segment's in-point, swap on boundary (requestVideoFrameCallback where available, rAF fallback); angle = which source's proxy a segment uses. Click a word → seek; playback highlights the current word and auto-scrolls unless the user is selecting. Space/J/K/L. A-roll only in this task.
- Waveform strip under the monitor from the peaks endpoint (canvas), showing cut regions.
Acceptance: `npm run build` clean under strict TS; vitest for selection snapping, segment scheduling, and store reducers; Playwright against a mocked API (fixtures generated from real post_core output, committed) covering: select+delete, restore, move, set angle, swap take, 409 handling, undo/redo, 20k-word scroll performance budget, playback crossing a cut boundary swaps elements and lands within 1 frame of the expected in-point (use a tiny generated test video). Document `npm` commands in `web/README.md`.
Only touch `web/`, plus minimal additive endpoints in post_core/edit + post_api (with tests). Another agent may be working in `post_core/recipes/` — leave it alone.
