# T38 Resolve read-back: the editor's cut wins (port sync_edit), after H1
Why: the main lesson of finishing Acme (9/19–9/28) is that once the edit is in Resolve, the editor's cut is the
truth. Placements are read back by media file, never by time; review notes live as Resolve markers; regenerated clips
replace the existing item in place. Post3 only exports one way, so the first trim in Resolve strands every later
regeneration. Do this after H1 confirms what an OTIO import keeps, and only once the Sample short is in Resolve with
B-roll that may need regenerating. It is not needed to ship the first version.
Read first (read only): `~/.claude/skills/resolve-place/scripts/sync_edit.py`, `replace_inplace.py`, `place.py`,
`test_sync_edit.py`; `export/otio_export.py`; H1 notes in docs/HANDOFF.md.

   is reliable) and map each item back to the Post3 asset/span by media file identity (content hash/fingerprint), not
   by time. Report moved, trimmed, deleted, and unknown items; write `.post3/resolve/<cut>_readback.json`.
